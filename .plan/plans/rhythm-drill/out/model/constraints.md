# Constraints

- **stack** (FIXED): TypeScript (strict; build runs tsc --noEmit) + Vite 8 + three.js 0.186. No UI framework: screens are template-string HTML in src/ui.
- **stack** (FIXED): Every drill extends Drill (src/drills/drill.ts), returns a DrillReport (0–100 score, stats, analytics) and is registered in DRILL_DEFS (src/drills/registry.ts) with 10 levels and 1/2/3★ thresholds.
- **stack**: All sound goes through the single WebAudio Audio class (src/core/audio.ts), unlocked from a user gesture. Today it only synthesises sounds; it does not play samples or music files yet.
- **platform** (FIXED): Static site on GitHub Pages: no server and no accounts. Uploaded audio never leaves the browser.
- **platform**: Desktop Chromium is the main target (pointer lock with unadjustedMovement). Firefox must still work.
- **other** (FIXED): Saves are small JSON in localStorage via store (src/core/store.ts), with backup export/import in Settings → Your data. Audio files cannot be stored there (~5 MB limit).
- **performance**: Shots resolve at the instant of the click: Game.button() calls fire() and then drill.onShot() synchronously inside the mousedown handler (ShotResult.at is game-clock time).
- **other**: Tests are vitest in a node environment (tests/*.test.ts). Beat detection, chart building and scoring must be pure functions that run without WebAudio or the DOM.
- **legal** (FIXED): No copyrighted music in the repo. There is no built-in song; test audio is generated by a test-only helper (D11).
- **other**: All copy is in plain words for beginners, in the same voice as the coach and Field Manual.
